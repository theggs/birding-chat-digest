# 报告格式

以下模板按默认的“分类简报”风格书写；其他风格把节标题换成 `#### 1. <主题要点>（<时间段>）`，正文成段书写。

```markdown
# 观鸟群日报 · <任务名>
日期：<YYYY-MM-DD>
统计区间：<window_start> 至 <window_end>（<时区>，含起点、不含终点）

## 分组总结

### <群名 1>

#### 1. 地点：<地名>（<时间段>）

- **<鸟种>**：<数量或状态>，<具体位置和时间>（「<报告人>」）。

#### 2. 话题：<议题>（<时间段>）

<一句话写明议题。>

- <论点或经验>（「<持有者>」）。

#### 3. 活动召集

- <时间、地点、内容、联系人>

### <群名 2>
...

## 数据覆盖

| 群名 | 抓取条数 | 状态 |
| --- | --- | --- |
| <群名 1> | 904 | 完整；图片 118、表情 43、系统消息 3 |
| <群名 2> | — | 失败：<错误摘要> |
```

## 数据覆盖必须写明

- 每个群的抓取条数（`fetched`）和状态。有 `error` 的群写“失败”和错误摘要，**不写成 0 条消息**。
- `source_coverage` 中任一源日期的 `total_count` 与 `fetched` 不一致时，写出源日期和差额。
- 图片、表情、系统消息的数量（取自 `type_counts`）。
- 无法取得公开昵称的发言者数量（`unresolved_senders` 大于 0 时）。

## 不进报告的内容

- 原始消息全文、内部文件路径、密钥或令牌。
- 处理过程说明（“已读取 3 个文件”“未做视觉理解”）。

## 归档（可选）

定期运行时，建议每期把报告保存为 `archive/<日期>/<任务>/<时段>/report.md`，长图为同目录下的 `report-preview.md` 和 `report-preview.png`。同一期重跑时直接覆盖，目录里只保留本期最新、有效的一份结果；每次运行的报告通常已经发到对话或任务结果里，不必在本地再留历史副本。取数失败时把错误说明存为 `error.md`，之后重跑成功时删除它。启用审稿时，初稿不写入归档，归档只保存终稿。
