# 定时任务提示词模板

前提条件：本机已运行 chatlog。

如需每天定时生成日报，可使用任何能够定时调用 AI Agent 的工具（例如 cron 配合 Agent 命令行，或 Agent 自带的定时任务功能）执行下方的提示词。建议如下：

- 每个批次（即一组群和一种总结风格）对应一个定时任务。每个任务的全部要求都写在该任务自己的提示词中，任务之间互不依赖。
- Agent 只需安装 `birding-chat-digest` skill，无需另行编写全局指令。

使用前，请将提示词中的 `<…>` 替换为实际的值。

---

```text
使用 birding-chat-digest skill 生成观鸟群日报。
任务名：<任务名>；批次：<批次 id>；时区：<Asia/Shanghai>；风格：<分类简报 | 简报 | 时间线回顾 | 详略回顾>。

1. 确定本期
首先读取工具返回的当前实际时间，不把聊天里的日期当作当前时间。本任务的计划时点为每天 <12:05 和 21:05>（统计区间按 12:00 和 21:00 划分，启动延后 5 分钟，确保区间已经结束）。
- 自动触发或手动试运行未指定时点时，取当前时间之前最近一个计划时点。
- 用户指定了日期或时段时，以指定为准。
- 确定后固定本期的日期、时段和统计区间。<12:00 时段：前一天 21:00 至当天 12:00；21:00 时段：当天 12:00 至 21:00。>

2. 取数
确认本机 chatlog 已启动（<http://127.0.0.1:5030>），然后运行：
python3 <skill 目录>/scripts/fetch_chatlog.py --groups <groups.json> --start <本期起点> --end <本期终点> --tz <Asia/Shanghai> --out <输出目录>/<日期>/<批次>/<时段>
chatlog 连不上或脚本整体失败时停止并报错，不读取旧数据。退出码为 1 但写出了 index.json 时，按其中的 error 如实报告失败的群，其余群照常总结。
<已编译副本读取器时：改为运行 python3 <skill 目录>/scripts/run_snapshot.py -- 加上与上面相同的参数（不含 --server）。>
取数后核对 index.json 的 window_start/window_end 与本期一致；不一致时停止并报错。
以 index.json 为准读取各群全量消息。

3. 总结
按 skill 的流程和“<风格>”风格逐群总结，报告标题为“观鸟群日报 · <任务名>”。
以下要求适用于报告正文和预览长图：
- 叙述使用正式、自然的中文，不造词，不生硬直译，不使用口语或方言，不编造简称、缩写。原文中的简称、缩写和特殊称呼不自行猜测补全、替换或更正。
- 不要对聊天内容进行冗余的补充说明，不逐项交代聊天中缺少哪些信息；仅保留影响主要结论的不确定性、分歧、纠正及必要的数据披露。

4. 归档
完整报告保存到 <归档目录>/<日期>/<批次>/<时段>/report.md；重跑时直接覆盖，只保留本期最新结果。取数失败时把错误说明存为 error.md，之后成功时删除。
<需要分享长图时：按 skill 的 preview-image 规范生成 report-preview.png，保存在同一目录。>

<启用审稿时：
4.5 审稿
完成报告后先不发布，交给 <审稿 Agent> 按 skill 的 references/review.md 对照原始消息审稿；审稿人只提意见。逐条核对意见，接受的照改，不接受的说明理由，再生成长图、覆盖归档并发布终稿，末尾附审稿处理结果。>

5. 输出
- 全程使用简体中文。
- 把完整报告作为本次任务的结果输出；生成了长图时一并给出图片。
- 只执行本批次，只按本提示词规定的风格输出，不参照其他批次。没有明确要求时，不触发其他任务，也不修改任何定时任务配置。
- 只读聊天数据。报告不含密钥、内部路径或原始消息全文。取数、渲染或归档失败时明确说明，不声称成功。
```

## 多个批次共用同一次消息获取

如果多个批次在同一时间运行，且数据来源相同，可以在获取消息时加锁：第一个获得锁的任务负责获取所有批次的消息，其余任务等待其完成后，直接读取本批次的消息文件。`fetch_chatlog.py` 本身不提供此功能；如有需要，可另行编写一个带锁的脚本来调用它，并在提示词中注明“只能通过该脚本获取消息，不得绕过”。
